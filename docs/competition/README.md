# 小保助教：让主讲专注讲课

小保助教是一位贯穿课前、课中、课后的 AI 助教。
它围绕保利威直播，为主讲整理资料、处理提问、执行互动。
下课后，课堂记录仍能用于复盘和下一次备课。

主讲负责讲好内容，小保协助照顾课堂。

## 我们解决什么问题

一位讲师开直播，往往同时承担多个角色。
讲内容时，要看公屏；学生提问时，要找资料。
想检验理解程度，还要切换界面、找题、发题。
下课后，聊天、口播和互动结果又散落在不同位置。

这些工作都重要，却不断争夺讲师的注意力。
小保把它们放进同一节课里，并提供随手可用的协助。

## 谁会受益

- **主讲**：少盯消息，少找操作入口，持续掌握课堂反馈。
- **运营**：协助处理重复问题，执行签到和公告等事务。
- **观众**：获得基于课程资料的答复，参与课堂练习。

项目以主讲为核心用户。
运营和观众通过同一场保利威直播受益。

## 一节课，小保如何参与

### 课前：带着准备开始

老师创建教室和课程，导入资料，与助教讨论教学内容。
助教协助整理大纲、讲义和结构化练习题。
确认后的备课可以带入本场直播，成为课堂答疑的依据。

### 课中：看见问题，也能执行操作

小保结合观众消息、备课和课堂转写处理提问。
重复诉求可以合并，缺乏依据的问题交给主讲。
老师还可以通过语音发起签到、公告或答题。
互动结果进入本课记录，为补讲提供参考。

桌面上的助教形象提供轻量入口和状态反馈。
需要处理问题时展开工作台，讲课时保留简洁入口。

### 课后：每次授课都有积累

口播、问答和互动记录保留在对应课程中。
老师可以继续与助教复盘，生成课程资料。
资料可选入知识库，备课也可复制到下一节课。
教室长期存在，每次开课保留独立记录。

## 项目最有辨识度的四点

### 1. 同时理解课堂内容与课堂事务

问答依据包含备课、选定知识库和本场口播。
主讲在课堂中的回答也可成为后续答疑依据。
这让助教能够围绕正在发生的课程提供帮助。

### 2. AI 的建议能够落到直播操作

项目接入保利威官方互动 SDK。
签到、公告和答题卡都有实际调用路径。
主讲的意图可以从语音进入工具，再进入直播间。

### 3. 主动协助与语音操作分工清晰

观众消息触发问题判断和处理。
主讲指令触发明确的课堂操作。
两条路径共用课程上下文，又分别约束操作权限。
主讲因此可以保留对课堂节奏的掌控。

### 4. 课程经验能够持续复用

备课、课堂记录和复盘围绕同一节课组织。
课程之间独立保存，公共知识库支持资料复用。
一次讲课的经验，有机会成为下一次备课的起点。

## 为什么与保利威结合

保利威提供真实的直播消息、课堂互动和平台数据。
小保在这些能力之上，连接课程语境与主讲意图。

- 官方互动 SDK：发起签到、公告和答题卡。
- 聊天室协议接入：接收观众消息，发送课堂答复。
- Open API：校验频道，管理题目，获取课堂数据。

这些接口进入核心授课流程，直接服务项目价值。

## 作品形态

原生 macOS 桌面应用，采用 SwiftUI 与 AppKit。
桌宠负责快捷入口，工作台负责课堂事务。
教室承载备课、资料和课后复盘。
