# 小保助教

原生 macOS 桌面直播助教。SwiftUI + AppKit + SwiftPM，最低 macOS 14；macOS 26 及以上使用原生液态玻璃。

## 运行

```sh
./scripts/build.sh
open dist/小保助教.app
```

菜单栏默认常驻小保助教图标，提供显示桌宠、开始助教、设置、课程回顾和退出。桌宠右上角也有菜单，下方按钮启动独立语音指令。没有菜单栏开关、唤醒词、快捷键设置或悬浮侧栏。

`open dist/小保助教.app --args --preview` 使用独立临时数据和模拟待处理消息，发送按钮只完成本地交互，不向聊天室发送。先退出运行中的实例再切换启动模式。

## 设置

- 助教：昵称、男女桌宠形象、回答风格。聊天室不配置自定义头像。
- 知识库：默认列表；命名新建后进入详情；独立管理文件和 FAQ。
- 连接与模型：回答模型服务列表（兼容接口、Anthropic）、自定义地址、独立密钥、模型列表、测试连接和默认服务。Jev 决策与 ASR 单独配置。当前语音协议适配千问实时 ASR。
- 课程沉淀：每场课程的转写、问答、金句卡片、未答问题；导出 Markdown 或加入指定知识库。

凭据存放本机 `~/Library/Application Support/LiveAssistant/credentials.json`（仅当前用户可读写），普通配置和知识库位于 `~/Library/Application Support/LiveAssistant/state.json`。课程转写和卡片在同目录的 `Courses/<场次 UUID>/` 下自动保存。模型密钥不会从其他项目自动复制。

## 当前实现

- 一男一女、各 8 个动作、每个动作 4 帧；基于生成图集绘制，脚底对齐。待机约 7 秒眨眼一次，提醒动作结束后静止；支持系统减少动态效果。
- 多条待处理气泡并存，独立操作卡片，回答草稿不会被新消息覆盖。普通提示 5 秒收起。
- 保利威 Socket.IO v2 连接、消息去重、文字发送确认、图片和 PDF 上传/发送。图片走 CHAT_IMG，PDF 走 SEND_FILE。
- 消息判断、同类问题聚合、知识片段判定；回答服务生成结构化答案并核验依据；无依据或失败交主讲。
- 点击录音、停止后等待服务端最终结果；口述回答保留原文，明确的通知和文件指令直接执行，目标不清楚时追问。主动指令期间暂停持续录音，避免混入课堂转写。
- ASR 持续转写自动写入文本文件；Jev 判断是否值得提炼，回答模型从原文选择金句，生成 PNG 并保存。金句定时检查后自动发送，练习题手动点击发送。
- 结束本场归档未答问题。问答、转写与卡片可写入知识库，未答问题不会作为答案依据加入。

## 验证与边界

`swift test` 覆盖知识库隔离、答案来源/数字校验、低置信度处理、持久化与损坏文件保留、服务地址校验、旧配置迁移和课程记录编码。

本轮完成本机编译、签名和部分真实界面操作。未提供本项目的保利威/模型凭据，尚未完成真实聊天室、模型、ASR 和上传端到端联调。下载目录技术文档的历史“已实测”不代表此 Swift 实现已经实测。

暂未实现：开播软件画面控制、截图、删消息、断线历史补拉、token 自动续期、私密回复。重连有次数限制；过期需要手动重连。没有承诺第三方共享屏幕时能自动隐藏桌宠。

Word/PPT 的解析与上传尚未开放；当前知识库支持文字版 PDF、UTF-8 TXT/Markdown 和 RTF。文件发送目前限制为 20 MB 内 PDF/PNG/JPG，这是客户端限制，不代表平台上传上限。

当前为本机 ad-hoc 签名开发包，未公证、未发布。界面测试的预览记录与真实课程隔离。

## 素材

人物图集由本轮内置 imagegen 生成，源文件保存于 `Sources/Assistant/Resources/male.png` 与 `female.png`，生成提示词保存在 `docs/malePrompt.txt`、`docs/femalePrompt.txt`。运行时按 4 列 × 8 行取帧，不依赖外部素材路径。

`live-smart` 仅用于理解已有 Jev / ASR 接口经验；本项目没有复用其网页 UI 或 Node 运行时。

## 0.2.0 业务流程（2026-10-15）

以下说明替代上文历史版本的确认发送、归档依赖及界面名称约定。

- 互动管理：违规消息、消息聚合；智能回复：智能答疑、欢迎总结、金句提炼；课程沉淀：课程归档及产物选项。异常反馈内置，无独立开关。
- Jev 对观众消息分类并关联最近问题。按消息 ID 去重、用户 ID 计数；待答同类问题聚合，近期已答问题不反复刷屏。自动答案检索知识库、本场转写和主讲回答，并再次验证事实依据。模型失败或无依据保留待答。
- 问题和重要反馈置顶；提醒提供查看与忽略。流消息只展示最新进度/结果。主讲回答、自动回答、违规处置和工具执行都归入持久化已处理记录。
- 每 3 分钟整理新增聊天室讨论（只给主讲）；每 2 分钟有新人且有转写时发欢迎总结；金句每 2 分钟检查一次，首次第 3 分钟，与欢迎总结错开 1 分钟。关闭能力或切换场次后，旧生成任务不能继续发送。发送结果不明时暂停该自动发送任务，可核对聊天室后重新开启对应开关。
- 每 45 秒检查新增转写及问答，持续生成知识点、练习题及参考答案；不足完整内容不强行生成。引用原文用于来源校验。题目在本场讲师笔记点击发送为答题卡，不自动发布。
- 知识点补充到知识库默认关闭；开启后在“课程知识”库按场次更新独立文档，避免写入任意现有资料和重复追加。
- 设置入口改为课程回顾，按频道和时间展示每场记录；优先用平台 sessionId 识别场次并查询实际开播时间，尚未核实则明确标记接入时间。重连同一场恢复记录，新场次隔离。历史详情无发送入口。
- 结束本场等待转写收尾，补齐实时笔记，生成全场总结、大纲、课后笔记。断线本身不结束场次。
- 语音操作接入工具注册表。兼容接口与 Anthropic 使用原生 function/tool calling；0.3.3 起移除本机 Codex 接入。参数明确直接执行，缺少对象或存在歧义时追问。工具结果进入流消息与已处理。
- 平台适配包括聊天引用回复、课件、公告、签到、答题卡、问卷、抢答、计时器、卡片推送、即时抽奖、报名抽奖以及禁言/踢出。发送文字沿用原生 Socket.IO；互动通过官方 `@polyv/interactions-launch-sdk@0.7.0`（npm 发布包）及 WebKit 原生传输桥；库文件为未修改官方 UMD 包，网络请求仅允许保利威 API 域名。
- 踢出/解除踢出采用官方聊天室 SDK 协议，房间签名由程序自动计算，无需单独的管理 Key。已核对 frontend/chat-sdk 的 ui/assistant/src/demo/demo-main/mixin.js（getRoomSign）及 core/src/controller/user/index.ts（addKicked/removeKicked），并与客户端 sendKick 实现交叉确认。旧公开文档“Key 咨询客服”的说法不作为用户配置要求。
- 设置中的消息判断、语音转写仅填写 API Key。语音固定北京地域、`qwen3-asr-flash-realtime` 与 `dashscope.aliyuncs.com`。官方确认旧域名仍可使用，不要求填写 Workspace ID：https://help.aliyun.com/zh/model-studio/qwen-asr-realtime-interaction-process 。旧配置的模型/地域不再覆盖固定值。

验证命令：`swift test`、`node scripts/check-interaction-sdk.cjs`、`./scripts/build.sh`。
测试包含官方 SDK 在真实 WebKit 中通过模拟原生传输发起公告/签到，不会向生产频道发送。真实频道权限、真实语音识别、模型工具调用和各观看端展示尚需提供对应凭据后联调；本地测试通过不代表生产端到端通过。

每次点击开始上课，运行日志独立保存在 Application Support/LiveAssistant/Logs/。记录连接、场次、分类、聚合、回答、转写、笔记和工具执行，不记录鉴权凭据或完整讲课原文。课程回顾提供导出日志 ZIP；连接设置可打开日志目录。

真实视频测试资料位于 test-fixtures/BV1yipB6rE7U/。双击课程资料.xblesson 导入知识库与测试能力配置；双击启动观众模拟.command，输入频道号，按倒计时从头播放视频。脚本不模拟主讲，也不把管理员消息冒充观众。

## 0.3.1 备课与课程会话

教室对应频道，每节课有独立聊天、备课和资料。支持提前建教室、创建备课草稿、导入文字资料、AI整理大纲、讲义和结构化答题卡、确认备课和手动存入知识库。开课可选择已确认备课并自动带出频道，也可以手填频道后选择待开课课程或新建一节课；公共知识库独立选择。

无备课开播仍自动建课。平台场次确认后才消耗备课，关联时冻结本场快照；同场重连不覆盖原备课，重复开播新建session。旧版频道聊天保留为“历史讨论”。备课题目为结构化单选/多选答题卡：生成时保存本课，确认后可同步频道题库，直播时手动或语音发起；创建不会自动发送。资产按备课、课堂记录、复盘分组。

本版界面尚待用户方便时验收，不会自动打开应用。非界面验证记录见 `docs/preparation-sessions.md` 和 `evidence/preparation/`。
